## 3. Decision track: runner written and offline-verified

New root `C:/Users/kevin/ai_bench/decisions-20261005-v1`:

- `worker.py` speaks `/v1/systemone` over the 18 frozen windows, one `noul`
  question, and records `p_stuck` and request latency.
- `score.py` reproduces the frozen 0.85 threshold and the 3 s warm-p95 gate, and
  counts stalls caught (4) and false alarms (14).
- `run.py` provides `preflight`, `runtime-check`, `selftest`, `screen MODEL`, and
  `audit`. `screen` launches llama-server under a Windows Job, waits for `/health`,
  probes `/v1/systemone`, runs the worker under the memory/paging watcher, stops
  the server, and writes metrics.

Offline verification (no model, mock HTTP server): the self-test drove all 18
windows through the client, confirmed the request shape (`questions.stuck.type ==
"noul"`), the probability extraction, the latency measurement, and the scorer.
Result: 18/18, 4/4 stalls caught, 0 false alarms, latency gate passed. Evidence in
`decisions-20261005-v1/evidence/selftest/`.

The input carries no id, so the frozen set is matched by order; `score.py` asserts
the id set. The `state` is sent as a JSON object; a `json`/`text` switch is present
in case the server wants a string state. The first live step must be the sampling
probe and a single-row shape check, because the server has not been exercised yet.
