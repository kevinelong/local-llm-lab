Two more in-window sm_120 confirmations, both new today:

- **`#6956`** (2026-11-24T02:42:44Z, 3 comments): **RTX 5070 Ti 16 GB (sm_120), driver 621.14, Windows 11
  build 26200**, source build of 0.2.20. Loads fully, prints `ready:`, then the first request kills it at
  warm-up; **`kv_stream: reset` fails with the same error**, which the reporter reads as an address-space
  problem in new kernel code "rather than one of the speed-switch paths". Swapping the **0.1.63** binary
  back in, same config and env, runs normally. `Soluify` (04:31Z) reproduces on **sm_89 RTX 4090 with the
  prebuilt** (0.1.66 crashes, 0.1.64 works), so it is not the source build, not 512K YaRN and not DFlash2.
- **`#6994`** (2026-11-24T08:38:01Z): **RTX 5060 Ti 16 GB (sm_120), driver 621.24**, engine 0.1.66
  prebuilt, **Unsloth UD-IQ4_XS (3 shards, installed from Strata's own list)**: the **1-token** window
  captures cleanly in 10-12 ms on every attempt, wider windows fail, and the control plane retries
  **38 engine starts / 34 verify failures** in one log. Three secondary defects it names are the ones this
  lab already carries as rules: **`GET /health` returns `loaded: true` while
  `/v1/chat/completions` returns 503**, **Stop load does nothing during the retry cycle**, and the cycle
  ends only when the app exits. Same log: `Windows commit: 0.6 GiB left of a 135.9 GiB limit` and
  **`large pages refused for 59,523,465,216 B ... VirtualAlloc error 1314`**, plus a **12-switch** sm_120
  list that differs from the 13 the 11-22 file recorded (`ADAPT_FETCH` here instead of
  `VERIFY_DEVICE_HITS`) - a readback that must be quoted per build, not assumed.

**Root cause, and it is settled: `#6987`** (2026-11-24T07:50:54Z, **closed**, 5 comments). The four Q8_0
tensor-core hyper-connection kernels in `engine/src/kernels/cuda/fused_gr.cu` stage their weight rows in
`__shared__` and then read them back through `q8_ld16`, which is **`__ldg` (`ld.global.nc`) on CUDA** - a
global-space hint applied to a shared-memory address. `compute-sanitizer --tool memcheck`:
`Invalid __global__ read of size 2 bytes ... 29,197,646,887 bytes after the nearest allocation`. The fix
is a plain-load variant (`q8_ld16s`) at **16 call sites** across the four kernels; the global `q8_inject`
reads keep `__ldg`. The reporter's own numbers show the fix is not a retreat:

| | 0.1.63 | 0.1.66, `HC_Q8_TC=0 HC_Q8_BF16TC=0` | **0.1.66 + patch** |
|---|---|---|---|
| decode, greedy, 3 short prompts x2 (tok/s) | 151.3 | 161.6 | **166.7** |
| decode, thinking on | 121.3 | 122.8 | **131.0** |
| memcheck invalid reads at first window | - | - | **0** (unfixed: 4,096) |

`ThatsR4d` (2026-11-24T10:16:50Z) closes the loop: **"0.2.21 is out today and fixes it ... The 0.2.21 fix
(`f5da789`, from `#6714`) switches the same 16 shared-memory reads in the four TC kernels to a plain
load."** That is the item the release body calls "#6713".

**Applies here?** **Yes - it would have aborted every request on this box**, and this lab would have
written the 0.1.66 bump up as "unmeasured on our card" while a 5070 report sat in a thread we had already
read. The lesson is mechanical, not rhetorical: **`gh api .../issues/N` returns the body and the comment
count; a comment arm added after the first read is invisible unless the thread is re-fetched**. Every
Strata row from here re-reads the whole thread of any issue it cites, at cite time.
**Test:** none needed for 0.2.21 - but the *next* engine row still declares the `HC_Q8` pair and reads the
switch list back, because `f5da789` is a patch whose regression surface is 16 call sites.
**Cost:** an edit.

## 3. [GH] llama.cpp: Inkling 2's attention **was not running fused Flash Attention at all**, and three PRs cut the prompt-processing buffer by 2.5-3.4x

The best technical thread of the window, and it explains a number this lab already holds.

**`#32740` "ggml: compact bias on the existing FLASH_ATTN_EXT"** (26 comments, merged
**2026-11-23T17:17:11Z**, commit **`239242322`**). Its own overview: *"Without this patch, even when FA
was on, the model effectively ran a non-FA route, materializing all the intermediate activation tensors,
which read to enormous amounts of VRAM usage."* The maintainer asked for the pure ggml contract only, so
it adds one FATTN parameter rather than a new attention op.

**`#32752` "[Inkling 2] Build mask in chunks"** (closed; 13 comments) is the sizing half, measured on an
RTX 6000 Ada 48 GB - **compute buffer, GiB, master -> PR**:

| ctx | `-ub 512` | `-ub 1024` | `-ub 2048` |
|---|---|---|---|
| 32k | 3.28 -> **1.28** | 6.56 -> **2.28** | 13.13 -> **4.57** |
| 90k | 8.69 -> **3.19** | 17.39 -> **5.87** | OOM -> 11.76 |
| 200k | 19.13 -> **6.88** | OOM -> 12.62 | OOM -> OOM |

**`#32883` "inkling2: query chunking"** (open prototype, created 2026-11-23T14:03:19Z, 3 comments) does
the same for query rows with a **1 GB per-tensor budget** (1,024 tokens at 262,144 ctx). Its own
declaration is the one a lab row must carry: *"as results are different with different ub"* - so this PR
is a **change to the batch-invariance contract**, not only a memory win.

**And the failure it produces is now reported: `#32910`** (2026-11-23T21:33:11Z, 2 comments) - **GTX
1050 Ti, 16 GB RAM, build 12672 (`51831d47d`), CUDA 12.4, `-DCMAKE_CUDA_ARCHITECTURES=61`**, model
`Inkling-2-Mini-UD-IQ4_XS` (15.73 GB, arch `inkling2_loop`):

| command | CUDA0 request |
|---|---|
| `-c 16384 -cmoe` | 8,364.35 MiB |
| `-c 4096 -cmoe --no-repack --no-warmup` | 7,172.35 MiB |
| `-c 2048 -ngl 0 -cmoe --no-repack --no-warmup` | **7,310.63 MiB** |
| `-c 2048 --fit off -ngl 3 --no-warmup -ub 128` | **7,119.54 MiB** |

Nearly independent of `-ngl`, `-c`, `--fit`, `-ub` and `-cmoe`, so on a 4 GB card it cannot start with

**Tag arithmetic, computed with `compare` and not from dates:** `239242322...b12676` -> ahead 6, behind 0,

**Consequence for the row we already hold:** the 11-23 file's SOTAAZ arithmetic (**32K `-ub 512` = 3,356.2
