## 3. [GH] **`#7206`** puts an `0xC0000005` on the **first prefill** across **both** backends, and the cause the vendor names is a default that arms itself **on Windows with one AMD card and an expert profile**

**`#7206`** (2026-11-26T03:34:47Z, **8 comments**): Qwen3.8-Flash-Next **UD-Q4_K_XL** on an RX 7900 XTX
(gfx1100, Windows 11, ROCm 10.2, `--resident-experts`, `--expert-profile` 24,576 ranked pairs,

- **A CUDA reporter reproduces it at the same step** (`BlackBox-Labs`, 06:54Z): RTX 3090 sm_86,
  IQ3_S pack, *"the engine loads, the drafter comes up, it captures the 1-token window, and then it

  `strata.exe`** as the faulting module, offsets `0x6fe94b` (0.1.67) and `0x6fbc8b` (0.1.69).
- **Then it stopped reproducing** on that box (08:30Z) after `strata-inkling` on the second card was
  restarted: all four combinations of `STRATA_PF_FUSED` / `STRATA_PREFILL_TAIL_LOAN` booted,
  **including the control with no switches**. *"So I can't say which factor mattered."*
- **Every crashing start took the unbuffered file-tier path** and built a **55-58 GiB page-locked RAM
  copy**: `the GPU cache's fill and the RAM copy read unbuffered`, `mapped pinned cache complement
  ready: resident 57.69 GiB, pinned 57.69 GiB`, then `prefill plan inputs: 71.7 GiB experts, 12.7 GiB

- **The vendor's diagnosis names a self-arming default**: since **0.1.65 (0.2.19)**, on Windows with
  an AMD card, a single GPU **and an expert profile**, the engine turns on **"pin by need"** by itself;
  the same change made mapped host buffers coherent and switched on RDNA3 speed defaults.
  **`STRATA_PIN_BY_NEED=0` fixed two of three** earlier reports of the same family (`#7016`, `#6795`,
  `#7123`) and **`STRATA_ARENA_PIN_GIB=8`** gave a third a stable start. **Not confirmed for this
  reporter yet.**
- **One operational gift**: *"Debug symbols are kept from now on"* (release body) - the vendor
  resolved **nine attached minidumps** with the 0.1.69 symbols.

**`#7207`** (2026-11-26T03:41:26Z, 3 comments) is the same class from the *user* side and it is a
warning for the env-var arrays this lab keeps proposing: RTX 3080 12 GB, DFlash2, UD_Q5_K_XL, KV q8,
128K - with a **tuned set of `STRATA_ROUTE_TAIL_SKIP`, `STRATA_ADAPT_FETCH`, `STRATA_PF_FUSED`,
`STRATA_PCIE_FRAC_DEFAULT`** applied together, generation **truncates at arbitrary points**, and after
re-tuning the numbers it becomes **token spewing** (out-of-order, nonsense, not garbage characters).
Removing all of them restores stable generation at **~10 tok/s**. The vendor's reply adds a concrete
declaration rule for this platform: **`STRATA_SET` is not a Windows setting** - it is the Docker image's
variable for advanced settings; on Windows use `strata launch --set NAME=value` or the model's
`"env"` block, *"if you put `STRATA_SET=...` in your environment on Windows, nothing reads it"*, and
**the engine log lists the switches it actually turned on**.

**Applies here?** `#7206`'s trigger is **AMD + expert profile**, which is not us, and its CUDA half is
one card of two RTX 3090s - so it is a **hazard class, not a datum**. `#7207` applies **fully**: this

## 4. [GH] **`#7154`** gets a maintainer answer: the auto-arm costs **+12 % on a homogeneous 8-core Coffee Lake**, and the coverage denominator is **`n_layers x n_expert` = 24,576**

The 11-25 file's section 2 item moved twice in-window, and both moves matter.

**A second rig, non-hybrid** - `semsmumi` (2026-11-26T07:28:53Z): RTX 3070 **8 GiB** (sm_86), driver
621.24, **i7-9700KF, 8 cores / 8 threads, no P/E split**, 64 GB DDR4-3200, PCIe 3.0 x16, Strata app +
engine **0.1.67**, Qwen3.8-Flash-Next IQ2_XS, `--expert-cache 846`, A-B-A with a cold prompt then two
warm 256-token generations: **39.02 -> 44.08 (`STRATA_L3_PF=0`) -> 39.69 tok/s**. A1 and A2 agree to
**1.7 %**, so the delta is **+12 % (±1)**, and quality is unaffected - **3/3 needle retrieval at 4k,
16k and 32k**.

**The maintainer-side reply** (`HenryInter`, 2026-11-26T13:50:11Z) accepts the generalisation and
supplies the mechanism sentence this lab should quote:

- *"Static 1/n slicing replaces work-stealing with a fixed assignment, so every phase gates on the
  slowest worker run even on identical cores: OS scheduling jitter, turbo transitions, and
  memory-controller contention ... Hybrid P/E cores just turn that tax into a structural ~2x."*
- **The affected population is therefore "≤13 GiB card + ≥8 workers + low expert-instance coverage -
  any CPU topology"**, not "hybrid CPUs".
- **And it corrects the arithmetic the 11-25 file relied on**: the denominator is **not** the
  per-layer expert count but `g.n_layers * g.n_expert` (`generate.cpp:10496`), pinned by a unit test
  at `kTotal = 48 * 512 = 24,576`. So a user's "846 of 877 = 96 % coverage" is really **a few
  percent**, the gate fires as designed, and **our own 1,500-of-24,576 = 6.1 %** figure (10-31
  ladder) is the right one.
- The decisive check it offers: **when the auto-arm fires, the start line says so** - the readback
  our shortlist already asks for.

**Applies here?** Yes, and it is now **topology-independent with a measured magnitude**: +12 % on
8 homogeneous cores, +45 % claimed on the hybrid rig, and this box's 24-thread ladder (8 / 16 / 24 ->
30.4 / 32.3 / 29.5 tok/s, 10-19) is the same "slowest worker" shape from the other engine.
**Test:** unchanged - `standard-v1` A/B of stock vs `STRATA_L3_PF=0`, interleaved, reading the
auto-arm's own line. **Cost:** two starts on a bump engine (0.1.47 predates it).
