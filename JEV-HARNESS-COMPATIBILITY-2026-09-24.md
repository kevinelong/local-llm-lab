# Jev harness compatibility: versions, settings and hidden requirements

September 24, 2026. Follow-up to [the initial research](JEV-RESEARCH-2026-09-24.md).

The deeper review confirms that some integrations need particular upstream versions and opt-in features. A custom harness fork is not generally required. The important distinction is between exposing Jev as a callable tool, automatically consulting it during a turn, and replacing compaction. These use different host APIs and cannot be enabled interchangeably.

## Pi: usable upstream, but our launch/config details matter

The installed Pi 0.86.1 documentation describes `context` as a deep-copied outgoing message view and separately describes `session_before_compact` for replacing a summary. Tool-result interception is another distinct stage. No custom Pi binary is needed for these documented mechanisms. [Upstream extensions](https://pi.dev/docs/latest/extensions), [installed version's documentation](../ai_bench/pi-lab-0861/node_modules/@earendil-works/pi-coding-agent/docs/extensions.md).

Local evidence is actually at `C:/Users/kevin/ai_bench/pi-lab-0861/node_modules/@earendil-works/pi-coding-agent/docs/extensions.md`; the installed `dist/core/extensions/types.d.ts` also contains the event/context APIs used by the candidate.

Five concrete setup issues:

1. **Choose the binary explicitly.** `pi-local.ps1` currently invokes the 0.85.1 bundle. An isolated 0.86.1 trial should name `ai_bench/pi-lab-0861/node_modules/@earendil-works/pi-coding-agent/dist/bundle/cli.js` directly.
2. **Load only the intended extension.** Pi documents `--no-extensions -e <path>` for disabling discovery while loading an explicit extension. A controlled trial also needs a separate `PI_CODING_AGENT_DIR`, session directory and skill policy. `--no-skills` is available. Package installed elsewhere does not mean this launcher loads it.
3. **Do not confuse offline startup with network isolation.** `PI_OFFLINE=1` disables startup network operations such as updates; it does not promise to block an extension's HTTP calls. Hosted Jev still needs a key and network access. Keep key values out of reports and source files. [Installed environment reference](../ai_bench/pi-lab-0861/node_modules/@earendil-works/pi-coding-agent/docs/environment-variables.md).
4. **Some plugins ignore the isolated agent directory.** QuentinDanblon uses `~/.pi/agent/fast-jev-compaction.json` unless `FAST_JEV_CONFIG` is set; its key-file override is `FAST_JEV_KEY_FILE`. MoonTory hardcodes `~/.pi/agent/jev-harness.json` and `~/.jev-harness/log.jsonl`. iefnaf also builds its global config path from the home directory. A lab launcher alone does not isolate these files. [Quentin source](https://github.com/QuentinDanblon/pi-fast-jev-compaction/blob/679041b8511515c9a0fcebd617afebabd87ae7f6/index.ts), [MoonTory source](https://github.com/MoonTory/pi-jev-harness/blob/8b05776a4302d6bfb891eaa1ef38f3d715f3ae45/index.ts).
5. **Reconcile the real context window.** Existing standard profiles declare 16k aliases and use compaction reserve/recent budgets of 4096/4096. The successful A3B placement screen used 8192. Pi 0.86.1's generic documented defaults, 16384 reserve and 20000 recent tokens, are unsuitable for that 8k experiment. Build a separate model entry with the actual server context/output limits and explicitly budget compaction. Do not copy the existing 32k roomy profile or change context without rerunning memory eligibility. [Installed settings reference](../ai_bench/pi-lab-0861/node_modules/@earendil-works/pi-coding-agent/docs/settings.md).

### Better matched candidate discovered

[MoonTory/pi-jev-harness](https://github.com/MoonTory/pi-jev-harness) already implements the loop observer we discussed. It checks repeated identical tool calls and can log decisions without blocking them. Its default guard can introduce confirmation dialogs, while its router filters tools and its pre-fetch uses ripgrep. The benchmark uses Jev as a grader, so our evaluation should keep independent correctness checks. This is a promising candidate, not a validated improvement.

A proposed first configuration, **not installed**, is:

```json
{
  "mode": "log",
  "route": false,
  "prefetch": false,
  "trim": false,
  "loop": true,
  "guard": false,
  "timeoutMs": 3000,
  "showStatus": true
}
```

Static source review confirms that loop state resets even with route/pre-fetch disabled, and that logging mode returns before blocking a call. The client still hardcodes `jev-latest`; add version configuration before reproducible tests. Its mode command changes memory only; session startup reloads the file. Missing or unreadable config falls back to active defaults, so our adapted lab version should instead fail to the selected observe-only behavior. Its route and pre-fetch use `Promise.all`; keep both off during the serial loop trial. [Loop implementation](https://github.com/MoonTory/pi-jev-harness/blob/8b05776a4302d6bfb891eaa1ef38f3d715f3ae45/tools.ts), [turn setup](https://github.com/MoonTory/pi-jev-harness/blob/8b05776a4302d6bfb891eaa1ef38f3d715f3ae45/route.ts), [client](https://github.com/MoonTory/pi-jev-harness/blob/8b05776a4302d6bfb891eaa1ef38f3d715f3ae45/jev.ts).

For a later Quentin compaction trial, set `pruneInBackground: false`, `requestConcurrency: 1`, and a pinned `model` in an explicitly selected config file. This avoids its default background overlap and four concurrent requests. It has no equivalent verified observe-only switch in the reviewed configuration; use replay first rather than mistaking disabled mode for scored observation.

## Claude Code: function hooks are the important distinction

Anthropic's own repository now publishes built-in **Mods**, implemented with function-hook modules. Its public discussion explicitly acknowledges `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`. This is an upstream experimental mechanism, not evidence that an unofficial patched Claude binary is required. Anthropic warns the interface may change between releases. [Official Mods source](https://github.com/anthropics/claude-code/blob/main/mods/README.md), [upstream discussion](https://github.com/anthropics/claude-code/issues/91870?timeline_page=1).

The tamaratran plugin declares a `modules` array in `hooks/hooks.json`, registers `session.compact`, and uses the engine's `$.http.fetch` adapter. Its checked-in declarations target 2.1.274. The newer `claude-jev` plugin reports live testing of this mechanism on 2.1.278. Our 2.1.266 binary contains the function-hook flag string, but that alone does not establish compatibility with either compaction API. Pin and verify the plugin's tested host version rather than assuming the flag upgrades the API. [Original hook instructions](https://github.com/tamaratran/fast-jev-compaction/blob/e3f262a7f4d42bd8dd32ced30d26176f7cb545b0/hooks/README.md), [newer plugin research](https://github.com/0x7067/claude-jev/blob/0b957628670e8c7b1f0eccbb988414d1e7198560/docs/claude-code-compaction-research.md).

The newer author's runtime research identifies additional gates: accepted workspace trust, hooks not disabled by managed policy, no safe/bare mode, and no isolated subagent compaction. It distinguishes modules from conventional `PreCompact`/`SessionStart` hooks. A conventional hook that prints context is not automatically a replacement for the summarizer. Treat these runtime observations as version-specific. Keep only one compaction replacement active and verify dispatch; module ordering can affect which implementation handles the event.

`claude-jev` also offers ordinary prompt/rule hooks without the function-hook flag. That does not make the entire plugin suitable for our current trial: it includes subagent routing, edit/turn checks, optional background dependency fetching, and Python commands. Those features require a separately scoped configuration. Do not enable its subagent routing under our current no-second-agent instruction. [Plugin README](https://github.com/0x7067/claude-jev/blob/0b957628670e8c7b1f0eccbb988414d1e7198560/README.md).

For simple Jev tools, `jev-code` uses ordinary MCP and does not require experimental compaction hooks. A source checkout needs its build output; its Pi extension imports that output. Its setup command can modify multiple user profiles, and its Codex `--project` option still registers MCP at user scope. Use an explicit target and review the changes before an eventual installation. [Per-harness setup docs](https://github.com/FrancoisChastel/jev-code/tree/051b492a201d5fe97dd26c422dcc5d7ed24b033c/docs/harnesses).

## OpenCode: V2 is a genuine compatibility requirement

The nrdz plugin reports a captured host payload from **2.0.7**, with SDK contract checks against **`@opencode/plugin` 2.0.7 and 2.0.8**. That package and API differ from older `@opencode-ai/plugin` examples. Official V2 documentation describes `Plugin.define`, `setup`, and `ctx.session.hook("context", ...)`. Installing this extension into our 1.17.15 profile cannot supply the missing V2 host API. [Plugin compatibility](https://github.com/nrdz-labs/fast-jev-opencode/blob/4c4de4dcffa0201502fcb682c80b807cfd248140/README.md), [upstream V2 API](https://opencode.ai/v2/docs/build/plugins).

Its defaults can also look like a non-working install:

- `dryRun: true` scores and logs without changing requests. This still calls Jev.
- `minMessageChars: 60000` skips short sessions.
- `preserveCurrentTurn: true` protects everything since the latest real user prompt.
- `protectedToolsMode: "truncate"` protects calls, but can shorten their results; use `"pin"` when both must remain untouched.
- `FAST_JEV_ENABLED` and `FAST_JEV_DRYRUN` are process-environment overrides; changing them in another terminal does not update an existing server.
- The config sits beside the plugin, while key lookup also checks `~/.config/opencode/.env`. Missing/invalid config falls back to observation. `/jev-prune` reports status; it does not force a prune.

[Exact configuration contract](https://github.com/nrdz-labs/fast-jev-opencode/blob/4c4de4dcffa0201502fcb682c80b807cfd248140/docs/CONFIGURATION.md).

For a future V2 trial, use a separate installation/profile and verify the server's version, SDK contract and actual outgoing payload. Earlier beta issue reports describe both discarded context mutations and mutations leaking into stored history. They are not proof that 2.0.7 has those defects; they explain why a successful plugin-load message is insufficient. [Reported dispatch problem](https://github.com/anomalyco/opencode/issues/44788), [reported persistence problem](https://github.com/anomalyco/opencode/issues/43731).

MCP remains a separate route for typed Jev tools on ordinary OpenCode. Its existence does not provide the V2 context-pruning hook. [Official MCP configuration](https://opencode.ai/docs/mcp-servers/).

## Codex: do not enable an obsolete feature flag

On our installed CLI, `codex features list` reports:

```text
hooks          stable   true
plugins        stable   true
plugin_hooks   removed  false
```

Therefore the community README's conditional advice about `plugin_hooks` does not apply to this binary. Hook definition/trust and execution are still separate checks. Official docs state that plugin installation does not automatically trust its hooks; review the concrete definitions through the host's hook UI before use. This is a host requirement, not a proposed extra approval for routine commands. [Official plugin hook rules](https://developers.openai.com/plugins/build/plugins).

The jcressler plugin preserves exact archives and supplies a recovery index around native compaction. It is not a transcript-pruning replacement. Its pinned hook file includes Windows commands, a 25-second `PreCompact` timeout, a 5-second `SessionStart` timeout, and `additionalContextLimit: 4000`. Jev mode separately needs `FAST_JEV_MODE=jev`, `FAST_JEV_ALLOW_NETWORK=1`, and a key in the actual Codex process. No current app settings were changed. [Pinned hook file](https://github.com/jcressler/fast-jev-compaction-codex/blob/8dc4bc70f4943454a81bf29af02e2737f445639f/hooks/hooks.json), [plugin instructions](https://github.com/jcressler/fast-jev-compaction-codex/blob/8dc4bc70f4943454a81bf29af02e2737f445639f/README.md).

Official `PreCompact` ignores plain stdout; structured output can stop compaction. `SessionStart` handles the post-compaction context path. Porting a Claude hook by keeping its event name but assuming identical output semantics is unsafe. CLI 0.156.1 evidence also does not prove that a separately bundled desktop runtime behaves identically. [Official hook semantics](https://learn.chatgpt.com/docs/hooks).

## Provider and SDK settings

| Route | Endpoint | Example model ID | Required key |
|---|---|---|---|
| TypeSafe direct | `https://api.typesafe.ai/v1/systemone` | `jev-1.13.0` | `TYPESAFE_API_KEY` |
| OpenRouter | `https://openrouter.ai/api/alpha/decisions` | `typesafe/jev-1.13` | `OPENROUTER_API_KEY` |

These are decision APIs, not interchangeable chat-completions model entries. Several extensions hardcode the direct endpoint, model alias, or key name. The [OpenRouter-specific fork](https://github.com/ingebyd/fast-jev-compaction-openrouter/blob/83e80eb4be76243f99c1c3cefa5414afb1b01300/src/request.ts) changes request construction and adds provider constraints; that is an adapter fork, not a custom Claude binary. Prefer the current documented model identifier over its moving alias. [TypeSafe model documentation](https://docs.typesafe.ai/models), [OpenRouter's own request examples](https://openrouter.ai/blog/insights/what-is-jev/).

LangChain's classifier is available through the provider package, but routing and tool-gating middleware require the `[experimental]` extra and imports from `langchain_typesafe.experimental.middleware`. The current router selects from the latest human message for the run; it is not inherently our history-aware per-step loop observer. No custom LangChain fork is indicated. [Official integration](https://docs.langchain.com/oss/python/integrations/providers/typesafe).

## Revised next step

Use the existing Pi 0.86.1 installation for an isolated **loop-observation** trial based on MoonTory's code, with a plain Pi control and deterministic repeat detector. Adapt config/log paths and model pinning first; keep pre-fetch, trimming, tool filtering and extra guard prompts off. This is closer to our intended test than merely exposing a Jev tool and hoping the model calls it.

Before a live trial, verify in order: exact executable/version; extension loaded; expected hooks registered; selected configuration actually read; synthetic event reaches the observer; returned decision logged; original tool input/output unchanged in observation mode. Later intervention tests must prove the outgoing request changed as intended and preserved history separately. Neither a package install nor an API ping establishes this chain.

Claude replacement compaction and OpenCode V2 pruning should be separate experiments on their stated versions. Keep our A3B memory gates, one local inference workload at a time, and cleanup requirements. This research did not install plugins, access keys, start inference, change startup settings or reboot.
