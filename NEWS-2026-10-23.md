## 4. [GH][VRAM] Memory-shaped reports from adjacent repos, which is where the numbers are

### 4.1 llama.cpp #30987: GTT is the AMD twin of the WDDM shared segment

**Source.** Issue **#30987**, "*Misc. bug: increasing -ncmoe!!! (or putting cmoe) leads to OOM on GPU*",
**closed 2026-10-23T06:40:56Z as completed**, 1 comment. Environment: **R9700 AI PRO, Mesa 26.2.5, Linux,
Vulkan, `--load-mode none`, b11783**, model Qwen3.8-Flash-Next UD-IQ4_XS merged.

- The report: increasing `-ncmoe` **above 32** (with *"plenty of RAM"*) fails with *"radv/amdgpu: Not enough
  memory for command submission"*; **decreasing below 32 works until VRAM is full**, and with `-ncmoe 32` the
  full VRAM can be allocated either by context or by `--moe-cache-mib`. A different quant moved the
  borderline to 29.
- The author's own closure, which is the finding: *"this was my gap in understanding of RADV drivers/llama.cpp
  specifics. If `--load-mode none` is used, **GTT is used for CPU kept experts**, GTT was OOMing while VRAM
  stayed not full. The more experts I pushed to CPU, the more demand of GTT."*
- **Why it belongs in this file:** it is the third named ceiling in the same family - pageable/pinned host
  memory charged against a GPU-visible budget - and it arrives with the counter-intuitive direction
  (**more offload caused the OOM**), which is exactly the shape of #30987's sibling on Windows
  (`--load-mode mlock` skipping >4 GiB buffers, 2026-10-19) and of FreeToken #55 (2026-10-22).
- **Applies: as a rule, not a config.** On this box `--load-mode none` with `--cpu-moe` is our measured
  baseline; the rule it imports is *declare which host-memory pool the offloaded experts draw from, and read
  the pool's usage, not free VRAM*.

## 8. [ARX] Research: the index advanced a full day - 222 new cs.CL/cs.LG listings

**Count first.** The API's newest **300** results across `cs.CL` + `cs.LG` are **222 dated 2026-10-22** and

Five read in full, chosen on our axes:

- **2610.31479 "Evaluating the Applicability of LLM Inference Optimizations on Apple Silicon"** - the most
  useful paper of the day for method. Four families (KV-cache pruning, speculative decoding, ported kernels,
  post-training quantization), four Apple machines, *"a common single-request decode workload, with matched
  RTX 4090 comparisons where possible"*. Findings: **KV pruning reaches up to 1.75x on Apple but can reduce
  throughput on desktop NVIDIA**; **all evaluated speculative decoding methods reduce throughput on Apple,
  despite reported 2-6x gains on server GPUs**; CUDA kernels transfer only partially (no async copy in
  public Metal), transferable parts give up to **1.20x**; quantisation gains vary by machine. Conclusion,
  quoted because it is this lab's own rule in a paper's words: *"a reported speedup is not a portable
  property of a technique alone but a joint function of technique, runtime, hardware contract, and workload
  regime."*
- **2610.31098 "RIFT: KV Cache Compression for Draft Models"** - names **decode staleness**: selection-based
  KV compression tuned on prefill loses the drafter's accuracy as output grows, so the fix is **refreshing
  the selection during generation**. Applies: our MTP/DFlash arms all run a draft model, and the 2026-10-10
  result (draft acceptance collapses on free-form code, 33 %) is the same failure seen from the other end.
- **2610.30791 "Gandalf: … Flash Storage Lifetime for KV Cache Offloading"** - SSD-backed KV tiers write more
  than the SSD's capacity over a production workload, *"shortening SSD lifetime from years to months"*;
  gating writes by access pattern kills hit rate, so they classify **attention types** that share history.
  Applies only if this lab ever puts KV on disk - recorded because the 2026-10-17 refusal of a remote KV tier
  was made on **tail latency**, and this adds **write endurance** to the same argument.
- **2610.31633 "BeNice! Closing Looping's Inference-Memory Gap via KV-Sharing"** - looped architectures grow
  KV linearly with recurrences; sharing the final recurrence's KV works on *some* looped models
  (*"KV-shareability"*), and the paper studies how to enable it. Not our architecture; kept because it is the
  cleanest statement that **KV memory can be a property of the architecture, not of the context length**.
- **2610.31646 "Low-Bit N-Gram Embeddings for Language Models"** - the memory number that makes the axis
  concrete: *"DeepSeek-V4.1-Flash, for example, allocates 196 billion parameters to its Engram n-gram
  memory"*, and 4-bit storage is investigated across nanochat/Llama/GPT-2 families. Applies as context for
  any DeepSeek V4.1 Flash port (§7): the n-gram tables are a memory line item no GGUF quant table shows.
- Adjacent, read at title/abstract level only: **2610.31657 "Cost-Aware Abstention for LLM-Based IT Ticket
  Classification"** and **2610.31662 "Reliable AI-Assisted Decisions via Selective Auditing"** - the
