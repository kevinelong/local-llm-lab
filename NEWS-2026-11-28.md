## 3. [GH] DFlash 2, the release's headline speed feature, **cannot be passed by `strata launch` on any platform** - three independent datapoints

`#7329` (2026-11-27T20:02:12Z, open, reproduced on the **0.2.23-cuda13 container**, 2x RTX 3090,
k3s): with `DRAFTING=dflash2`, the engine line shows `--draft dflash2` and **no `--dspark`**; the
memory line reads `DSpark took 0 MiB`; every completion reports `draft_n: 0` at 77.7 tok/s (the
no-drafter speed). Three separate causes, each a file-and-line claim:

1. **The launcher never supplies the path.** `setup.py`'s arg builder has
   `if dspark_path: args += ["--dspark", str(dspark_path)]` (~956/973) and nothing in the launch path
   passes it - `grep -rn "dspark_path" /opt/strata/terminal` finds only those two lines.
2. **`--dspark` wants an engine `.pack`, not the safetensors setup fetches.** `tools/dflash2_pack.py`
   builds the `DF2P` format successfully (**622.8 MB, 81 tensors** from incoai's `model.safetensors`,
   989,975,616 B, pinned revision `4f9088ea…`), while `inkling_family.DFLASH2_FILE` fetches the raw
   file beside the model.
3. **The launcher's `--draft` value is not in the engine's enum.** `strata-inkling --help` says
   `--draft auto|dspark|off`; the launcher emits `dflash2`. With `--dspark <pack>` present it **still
   logs `DSpark took 0 MiB`**.

**Two independent confirmations inside the thread, same day:** `demetree` on an Arc Pro B70 (SYCL)
reports that `--draft dflash2` "does not merely fail as a value - it **leaves the drafter off
silently**", because `ink_sycl_backend.cpp` sets `STRATA_INK_DRAFTER=dflash2` only for `--draft on`;
the working recipe is `--draft on` with the sidecar beside the model or `STRATA_INK_DFLASH2` pointing
at it, and the log then shows
`[ink_sycl_dflash2] loaded ... in 2.80s (5 layers Q8_ROW, slots=1, ring=2112, max_M*=8)` /
`DFlash 2 loaded: 635 MiB on the device`. A third reporter adds a CUDA datapoint that matches the
container one.

**Does it apply here?** Not to a row we hold (our Inkling rows are llama.cpp, and our Strata row is
0.1.66), but it decides **how a 0.2.23 bump row would be started**: our arms go through
`serve/server.py` configs and `strata launch`, so **a DFlash 2 arm launched by `strata launch` measures
no drafter while reporting success**. It also generalises the 11-26 file's "a fallback must announce
itself": here the fallback is silent in the *log* too, and the only witness is `draft_n` in the
completion timings.

**Instrument:** the existing `drafts accepted / offered` readback - which for `strata-inkling` is
`draft_n` in `timings`, and for Qwen is the `drafts accepted X of Y` line. **Cost:** zero (a read);
an arm costs one start.
