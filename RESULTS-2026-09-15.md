## Measurement and scoring

GPU probes used native Ollama chat, thinking disabled, temperature 0, 16k context, and an output limit of 384 tokens. One prose response supplied generation throughput; three short checks covered strict JSON extraction, exact instruction following, and arithmetic. This is a small diagnostic set, not a general intelligence benchmark. Speeds are API output-token rates, excluding loading and prompt processing. Single runs, especially Qwen's initial cold start, do not establish stable speed rankings.

Coding agents received the same dependency-aware task-manager specification, worked in separate directories, and had a 600-second limit. The historical scorer checks ten behaviors; the supplemental scorer checks never-reused IDs, priority ordering, a successful self-test that preserves existing data, and dependency-chain depth. These checks do not exhaust all sixteen specification requirements. A nonzero command can satisfy a rejection check; therefore even a largely broken program can earn a point. Supplemental self-test failure does not by itself prove data loss.

Smoffyy is a template revision, not a newly trained coding model. Although all three aliases use Q4_K_M and temperature 0, inherited sampling defaults differ: the Qwen baseline retains settings such as presence penalty 1.5. Harness prompts, repair strategies, token limits, and thinking behavior also differ. Treat the results as measurements of the recorded configurations, not isolated causal comparisons of models or harnesses.

## Pi configuration findings

The first Qwen hard run disabled compaction and ended at the context limit. Enabling compaction with 4,096 reserved tokens and 4,096 recent tokens avoided that immediate stop but led to a ten-minute repair loop. The original provider configuration also lacked an explicit Ollama-compatible response-limit field.

The corrected profile sets `maxTokensField: max_tokens`, explicitly sends `max_tokens: 8192`, and uses the smaller compaction settings. The no-thinking profile additionally sends `reasoning_effort: none`. Pi's model metadata flag `reasoning: false` alone did not disable Ollama's default thinking; transcripts contained thinking until the explicit API setting was added. No-thinking OmniCoder transcripts were checked for this distinction.

Sources: [Pi model configuration](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md), [Pi settings](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/settings.md), and [Ollama compatibility API](https://docs.ollama.com/api/openai-compatibility).

The initial OmniCoder run scored 3/10 and timed out; the corrected no-thinking run left a program scoring 9/10 and 3/4 supplemental checks after 482.83 seconds. Both response-limit configuration and thinking changed, so this does not isolate the benefit of disabling thinking. Its self-test still failed, and the agent eventually ended with `Stream ended without finish_reason`, despite a zero CLI exit code. This is a promising partial artifact, not a successful unattended run.

Smoffyy encountered repeated `Stream ended without finish_reason` errors during Pi repairs and then exited with code 0, despite an unsuccessful agent/program result. An attempted targeted stop reached it only after it had exited; it was not forcibly terminated. This is a model/runtime/harness integration failure in the tested setup, not proof that every Smoffyy deployment fails.

Aider used whole-file edits and automatic `python tasks.py test` feedback. It finished with a 3/10 program; normal startup did not call the persistence loader. Its transcript eventually reported 23k input tokens against a 16k server context, so context pressure is another limitation of that configuration. The historical 8/10 Aider result used a different model and architect setup and is not superseded by this run.

## Reproduce and use

From a project directory:

```powershell
C:/Users/kevin/ai_bench/pi-local.ps1 -Model omni
C:/Users/kevin/ai_bench/pi-local.ps1 -Model qwen
C:/Users/kevin/ai_bench/pi-local.ps1 -Model smoffyy -Thinking server
```

The launcher uses local Ollama, offline Pi settings, and the explicit no-thinking profile by default. `-Thinking server` restores server-default behavior. The model default remains Qwen; OmniCoder is an experimental coding option. Models stay on disk after tests, but resident model allocations are unloaded. The interactive launcher itself does not automatically unload a model on exit.

From `C:/Users/kevin`, choose a new label for every agent run:

```powershell
python local-llm-lab/benchmarks/round_20260915.py agent pi omni my-new-run no-think
python local-llm-lab/benchmarks/round_20260915.py unload
python local-llm-lab/benchmarks/summarize_round_20260915.py
```

`prepare` and `pull` can recreate local configuration and aliases; they are not needed to use the already-installed setup. Saved probe filenames and agent run directories are protected from accidental reuse. The runner is specific to this machine and directory layout.

### CPU-only baseline

Smoffyy Q4_K_M ran with `num_gpu: 0`, eight CPU threads, 16k context, and thinking disabled. The prose response generated 202 tokens at **11.41 tok/s**, taking 22.19 seconds overall including 4.14 seconds of loading. It passed **2/3** short checks; strict JSON failed because of Markdown fences, as on GPU.

Every request reported **`size_vram: 0`** and approximately 3.70 GB total model allocation. Total GPU usage remained **1,206 MiB** before, during, and after the test: the desktop still used the GPU, while model inference did not. Ollama's log explicitly recorded CPU-only projector handling and CPU/CPU_REPACK model buffers. See `probe-smoffyy-cpu.json` and `cpu-backend-evidence.txt` in the raw round directory. This verifies conventional CPU-only operation on this machine, not the performance of BitNet or other specialized CPU architectures. Eight threads were a fixed starting point, not a CPU tuning study.

## Recommendation after testing

Keep Ollama and the existing model/harness choices available. Keep Pi installed as an experimental local agent, with explicit no-thinking and server-default profiles. OmniCoder produced the strongest partial program in this round (9/10 plus 3/4), but its streaming failure and broken self-test prevent calling it a reliable unattended replacement. Qwen/Pi's corrected profile improved its partial score to 8/10 but still timed out and failed three supplemental checks. Smoffyy is a fast small-model inference candidate, not a demonstrated autonomous coding choice in this setup.

Before a broader model sweep, investigate the Pi/Ollama streaming termination errors and repeated repair/read loops on a smaller reproducible task. Then repeat matched configurations across several tasks and runs. The current scores justify that focused follow-up; they do not establish a general model or harness ranking. No tested configuration both finished cleanly and passed all external checks.

## Verification and resource handling

The Python helpers passed syntax parsing; new scripts and notes passed ASCII checks. Both Pi launcher profiles returned the pinned version, and the no-thinking configuration was checked for the local endpoint, 16k context, and explicit `reasoning_effort: none`.

Ollama models were unloaded before and after each experiment, including failures. Timed-out benchmark process trees were stopped by their exact process IDs. No unrelated browser, desktop, router, or assistant processes were killed. Initial inspection found no competing inference workload; model cleanup returned GPU usage close to the desktop baseline. Recorded preflight/cleanup samples are in every run's JSON.
